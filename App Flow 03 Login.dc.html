Every screen states which channel it used, because "I did not get the code" is the single most common support ticket in an OTP product.

Dev notes and edge cases
Sending OTPs over WhatsApp changes the failure modes. These are the ones that will bite.
WHATSAPP
Authentication template, pre-approved
Codes must go through an approved authentication-category template on the Business API. Get it approved before Phase 1; approval is not instant and a rejected template blocks every login.
DELIVERY
Treat the webhook as the source of truth
Accepted is not delivered. On a failed or undelivered callback, surface screen 05 rather than leaving the student watching a timer.
NO SMS
Say so on the screen
Students will wait for an SMS out of habit and then contact support. Every screen that sends a code names the channel it used.
ENUMERATION
Never confirm an account exists
An unregistered identifier gets the same screen and the same timer. Mask every destination. Rate limit by identifier and by IP.
SESSIONS
The emergency card is outside auth
Lockout, expiry and logout must never make the emergency card unreachable. It is served from local storage and a signed public link.
EDGE CASES
The ones that will happen
Number registered but not on WhatsApp · shared family number · college email deactivated after graduation · student changes number between semesters · code opened on the same phone that must receive it · WhatsApp Web already signed in on a hostel computer.
