Dev notes and edge cases

Error copy is a design surface here, not a string table. These are the rules it follows.
THE RULE
Say what survived
Every error names what is still safe before it names what broke. On a health vault, "your records are not affected" outranks the apology and the reference code.
NEVER A DEAD END
Two ways out, always
A primary action and an escape. The cached vault is the escape on every network-class error, which is why offline reads as a state rather than a failure.
THE CARD IS EXEMPT
Reachable from every error
Session expiry, lockout, maintenance and 500 all leave the emergency card working. It is served from local storage and a signed link, outside the session entirely.
NO BLAME
Ours or nobody's
A 500 says "on our side". A 403 says the scope was never granted rather than implying the user did something wrong. Neither asks the reader to contact an administrator.
TRANSITIONS
The loader is the brand
One veil, one direction, one heartbeat. It appears on cold start and on any navigation that waits on the network — never on an instant one, where it would be theatre.
EDGE CASES
The ones that will happen
Offline during an OTP · maintenance starting mid-upload · shared link to a deleted record · clinician whose scope closed while reading · 500 on the emergency-card link itself · session expiring on a camp station tablet.
