Flow 05 · Camp day

Four hundred students, four hours, no wifi.

Two products in one day. The student side is a phone app that has to work in a queue; the station side is a tablet operated by a volunteer under auditorium glare, possibly with gloves on, with no connectivity to lean on. They share a record and almost nothing else — the station is deliberately colder, denser and slower to make a mistake with.

Dev notes and edge cases
Camp day is the highest-risk surface in the product: real bodies, a volunteer operator, and no network.
NO BMI
Not computed, not stored, not shown
Height and weight are recorded as two numbers. Interpretation happens on the clinician side. This is the single most likely place for a well-meaning developer to add a badge — say no in code review.
OFFLINE
Offline is the default assumption
The station writes locally and syncs opportunistically. Queue depth is permanently on screen, never a toast. Input is never blocked on connectivity, and the roster is pre-loaded the night before.
PLAUSIBILITY
Warn, never block
A value far from the last reading raises a prompt the volunteer can override in one tap. Blocking a real reading is worse than recording an odd one — but the override is logged.
RELEASE
Nothing reaches the student unreviewed
Flagged findings wait for a practitioner's sign-off against a registration number. Only plain restatement auto-releases, and the student sees who reviewed it.
PRIVACY IN A HALL
The screen is visible to the queue
Show only what this station needs. Allergies and conditions appear because they affect the procedure; past results do not. No station shows a previous value except as a plausibility warning.
EDGE CASES
The ones that will happen
Student turns up without the app · two students with the same name · someone scans a friend's pass · tablet battery dies mid-queue · student walks off between stations · a reading taken twice by two volunteers · student asks to delete a value taken minutes ago.
