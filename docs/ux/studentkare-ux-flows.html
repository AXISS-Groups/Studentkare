For each dashboard: what every feature does, each journey told in plain words and then as steps, what blocks it today, and what could be built next. Then the flow design (who does what, and the states each record moves through), the system architecture, and a phased feature roadmap. What changed 2 – 5 Nov

  1. #297 Personal-record reader. A real document reader (Tesseract for images, embedded text for PDFs) that is off by default and has its own switch. A new optional consent, “Document AI analysis”, lets the student’s own documents be split into passages for search. Withdrawing the consent deletes every passage. Ayush can then answer “what’s in my record” by quoting those passages, and only for that student. Super admins get aggregate document counts (groups under 5 hidden) and doctors get counts of their own patients; both are API only so far.
  2. #291, #292 Design canvas now borrows patterns from the 1mg walkthrough: lab package Compare and fasting chips, a medicine “Often added with this” row, vaccine FAQs, five insurance cover cards (“Notify me”, no purchase), a wearables row in Profile, and more Ayush chips. Canvas and briefs only: the app screens are not updated yet.
  3. Rule L exception, drawn but not built: a “Recommended for you” product rail on Insights and Trends, shown only when a test is out of range, documented as founder-approved. The firewall code and the grants checks are unchanged.
  4. #294 Report upload with more document kinds (lab report, prescription, vaccination record, discharge summary): a flagged design concept. The shipped upload still saves only lab records, typed by the student.
  5. #293, #296 A reference catalogue under design/data/ (159 medicines, 96 tests and 20 packages, 22 vaccines, 13 insurance categories). Vaccine timings now follow the official MoHFW schedule.
  6. #285, #280 Dev-site guide and open-data loader merged; the phone-app type error on main is fixed.
  7. Code moves with no behaviour change: the pill-nav destinations, the nearby-provider lookup in the vault, Digital ID and the profile form now sit in feature folders.

What changed 24 Oct – 2 Nov

  1. Home moved. Student Home is now /home. The root /, the logo, /health and sign-in all land there. “My health” is no longer a sidebar item; /your-care still exists and opens from Home cards.
  2. #265 The doctor and admin approval queue (prescriptions, SOS dispatches, claims) is saved in the database, so it survives a restart and is shared across servers. Each row is limited to its student, campus and clinician.
  3. #266 If a student’s sign-in code can’t reach the chosen channel, it can fall back to a contact they have already verified.
  4. #269 Rule L fails closed in production: commerce staff see nothing clinical unless a grant exists.
  5. #277 The phone app gained Privacy & consent, Data rights, Visit summaries, the check-in pass, Security, the consent inbox and the Care circle.
  6. Flat icon tiles across the app, desktop grid layouts for the Mobile 2.0 boards, routing and architecture guard tests, and about 40 dead files removed.
  7. Dev site: #285 (merged 2 Nov) added a guide and an open-data loader for dev.studentkare.co only; production never seeds.
