## 1. PrescriptionUpload: a student uploads a paper prescription (SK-065)

**Approved by:** _(design reviewer + clinical lead)_

**Brief.** `design/screens/briefs/PrescriptionUpload.md` · icons `arrow-left`, `camera`, `check`,
`file-text`, `lock-5`, `share` · links to `Checkout`, `Medications`.

**Backend (ready).** `POST /api/health/prescription-uploads` (multipart `file`, any common image
format or PDF; type read from the bytes; virus-scanned, fails closed),
`GET /api/health/prescription-uploads` (own files with where each was sent and the outcome),
`DELETE /api/health/prescription-uploads/{id}`,
`POST /api/health/prescription-uploads/{id}/reviews` (send to one pharmacy; one pending review per file).

**Screen must.**
1. Camera and Files both post the same field. Show the API's own error text for too large,
   wrong type, infected and scanner offline; never a generic "something went wrong".
2. Never show extracted medicines: nothing is read from the file, and the screen must not imply it.
3. The brief's "Checkout" link becomes **send to a pharmacy** (picker from `GET /api/pharmacies`),
   not shop checkout. Rule L: a prescription never enters the shop cart.
4. States: empty, uploading, scanned and saved, sent and waiting, approved, rejected with the
   pharmacist's reason, offline (read-only list).

**Questions for the reviewer.** Copy for "approved" (it records verification only; nothing is
ordered until plan 2 ships). Whether HEIC from iPhones must be accepted at launch.

## 2. Prescription to order: choose a pharmacy, see the price, pay (Medications → Checkout)

**Approved by:** _(design reviewer + clinical lead + payments owner)_

**Briefs.** `Medications.md` (Tier 1), `Checkout.md`, `Payment.md`, `PaymentResult.md`.

**Backend (ready).**
- `GET /api/pharmacies?pincode=` → `{items:[{id,name,address,pincode,serviceablePincodes,openHours,delivery,pickup,servesPincode}],total,rankedBy}`. Never ranked by commission.
- `POST /api/dispenses {prescriptionId,pharmacyId,delivery:{mode,pincode}}`. Errors: 404 prescription or pharmacy, 409 expired prescription / already with a pharmacy / licence / mode or pincode not served, 422 bad mode.
- `GET /api/dispenses` → per dispense `status`, `quoteStatus` (NONE/QUOTED/PAYMENT_STARTED/PAID/CANCELLED), `pharmacyName`, `quoteId`, `totalPaise`, `rejectionReason`.
- `GET /api/dispenses/{id}/quote` → per line generic/brand/strength/form, quantity requested vs quoted, available, unit and line price; `partial`, subtotal, delivery fee, total, `canPay`.
- Pay: `POST /api/dispense-quotes/{quoteId}/payment {expectedTotalPaise}` → provider checkout or `{configured:false,status:"UNAVAILABLE"}`; then `/verify` → PAID / FAILED / PENDING. 409 quote changed / already paid / closed; 502/503 provider down or not connected.
- Cancel: `PATCH /api/dispenses/{id} {status:"CANCELLED"}`; after payment → 409 "contact support for a refund".

**Screen must.**
1. Show the full price before the student commits (DESIGN.md §6), and say clearly when a line
   can't be supplied (`partial`).
2. Medicine names appear only on this clinical screen, never on the shop, cart, receipts or
   notifications (DESIGN.md §7: notifications never name medicines).
3. Payment confers nothing: the payer sees amount and status only.
4. States: no pharmacies serve this pincode, waiting for verification, waiting for price,
   price ready, paying, paid, partly supplied, rejected, cancelled, payment not connected.

**Open gaps the reviewer should know.** No refund endpoint for prescription payments yet (a
paid order later rejected raises "payment needs refund" for ops). Quotes don't expire.

## 3. Pharmacy quote and dispense console (VendorRxReview, VendorOrders, DispenseRegister)

**Approved by:** _(design reviewer + pharmacist adviser)_

**Why it blocks.** Once priced dispenses merge, only a **paid quote** moves a dispense to
ACCEPTED. Without this screen, verified prescriptions stall. Ship it together with plan 2.

**Backend (ready).** `PUT /api/dispenses/{id}/quote` (owning pharmacy only, after RX_VERIFIED,
until payment starts; every line priced; quantity 0 = can't supply; delivery fee). Pharmacist
review of uploaded files: `/api/v1/pharmacy/rx-uploads/{id}/file-link` (two-minute link bound to
the pharmacist's session, every view audited), `/file`, `/approve`, `/reject`.

**Screen must.** Quote form per line with totals; locked once payment starts; packing only after
PAID; the uploaded-file viewer reloads its link on expiry; no patient identifier shown.

## 4. Teleconsult (student) and ClinicianConsultRoom (doctor)

**Approved by:** _(design reviewer + clinical lead)_

**Backend (ready).** `POST /api/consultation/{id}/media-token`: LiveKit token only for the
booking student or the assigned NMC doctor, only when CONFIRMED, from 15 minutes before the
start to 30 minutes after the end; audio/video only, no recording. LiveKit unset → 503
`MEDIA_UNAVAILABLE`. The existing consult dialogs already join calls; these screens replace them.

**Screen must.** Ask for camera/microphone only after Join; every call state (unavailable,
waiting, connecting, connected, reconnecting, ended, permission denied, no device, error);
crisis support reachable from the student screen; doctor room shows the visit's own record only
with the student's consent (existing consent rules).

**Questions.** Recording is off and must stay off unless a consent flow is designed. Call length
past the window. TURN server choice for campus networks.

## 5. ReportInsights: the report explainer (SK-047)

**Approved by:** _(design reviewer + clinical lead; AI constitution owner if any model is used)_

**Today.** No backend. A released lab report is a vault document with the doctor's review note.

**Proposal.** Phase 1 shows only the reviewing doctor's note, the lab's own reference ranges as
printed, and "talk to a doctor about this report" (links to Teleconsult, prefilled). No model
interpretation. Phase 2, only after sign-off: plain-language restatement routed through the AI
constitution (student-facing restatement is allowed; prediction and risk scoring are not, M18 /
Phase 8 SaMD path).

**Screen must.** Never colour-code or score a value without a clinician-approved range; never
gamify; notifications never contain values; crisis support reachable.
