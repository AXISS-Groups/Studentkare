# Canvas gap audit: every screen against the app (2026-10-20)

**Status:** active. The map and gap list the UI build agents work from. Goal: the app matches the 239-screen design canvas (`design/screens`).
**Rule:** `CLAUDE.md`, `DESIGN.md` §5–6. Tier 1 packages need a plan and a named reviewer before code; Tier 2/3 are built from the brief, picture and source.

## How this was checked

- **Canvas sync.** The live canvas (239 boards) was compared with `design/screens/source`. After mapping each `/_blob/<hash>` image back to the `design/assets` file ending in the first six hex characters of the hash, and keeping `../support.js`, **all 239 boards are identical to the repo copies.** The 21 boards that looked different (Appointments, DoctorResults, Landing, LandingClinician, LoggedOut, Main, Medications, Onboarding1, OrderSuccess, PreventiveCare, ShopHome, SplashPulse, SplashVault, VendorHome, WebAccount, WebConsult, WebLabList, WebLabTests, WebPrograms, WebShop, WebWellness) differ **only in image paths**: none is a design change, no source file needed rewriting, no blob lacks an asset, and no screenshot needs re-rendering. Board sizes and titles in the canvas index also match `screens.json`. (The repo has no screenshot-render script.)
- **Stale duplicate folders.** `design/screens/source/` also holds an older numbering (`03-student-web`, `04-campus-hostel-admin`, `05-doctor`, `06-partner-pharmacy-lab-clinic`, `07-super-admin`, `08-design-system-flow-map`) whose files differ from the canonical folders named in `screens.json`. Briefs point at the canonical folders. Build from those; delete the old ones in a separate PR.
- **Mapping.** Routes come from the module registry (`src/features/*/module.ts`), `WorkspaceScreen`/`WorkspaceRouteScreen`, the vendor, clinician and super-admin shells, and `src/native/App.tsx`. Candidate files were found by matching each board's copy (markup and its `t.kN` translation table) against the English catalogue and string literals in `src`.
- **check-icons.** `node scripts/icons/check-icons.mjs --screen <S> --files <files>` was run for every implemented screen with the files in the table. Cell format: `pass|fail (icons present/required)` plus `lucide`, `raw svg` or `text glyphs` when the script flags them.
- **Copy found.** Share of the board's visible strings found (exact, contained, or ≥60% word overlap) in the screen files' i18n strings and literals. Low numbers on consoles partly reflect live data replacing the board's sample rows; on student screens they mostly mean the copy was rewritten.
- **Rendered.** Vite (port 5320) with a SQLite test backend and demo sign-in; screens marked `rendered` were opened at 1440 or 390 px and compared with the picture. All others were judged from the brief, source and code (`code`). The super-admin screens could not be rendered: the demo admin is held at `/security` until 2FA is set up. Expo native views were not run.

Statuses: **matches** (layout, copy, states, icons close), **drifted** (built but visibly different), **partial** (some of the screen or its states), **missing**, **design-only** (system/reference boards). No screen is called `matches` unless its icon check passes.

### Biggest gaps

1. **Icons.** Only 3 implemented screens pass check-icons. Nearly every screen draws icons with `lucide-react` (all four console shells except the clinician one, the student workspace, the campus hub, auth) or raw `<svg>` (public site). The brief's names are almost never present.
2. **Student web shell (3b, 26 screens).** The signed-in web app uses the navy workspace sidebar with quick-nav buttons and a "Your care workspace" bar. The canvas has a top nav (Shop · Lab tests · Doctors · Health vault · Ayush, My orders, cart, avatar) and a light grouped sidebar (My care / Services / Account). Every 3b screen inherits the wrong frame.
3. **Campus console (26 screens).** There is no campus shell. Campus pages are tabs inside the student workspace (`InstitutionWorkspaceHub`). The canvas has its own sidebar (Campus / Safety / Public health / Admin), a scope picker, search and a 2FA chip. Seven campus boards have no screen at all.
4. **Phone boards on web (lanes 1–2, 86 screens).** At 390 px the web shows the web views (shop, workspace panels), not the phone boards (tab bar, phone headers, sheets). The Expo app covers some screens natively; it was not rendered here.
5. **Missing flows.** Search (typing, loading, results, no results), doctor results, result moments (payment, camp, refund), check-in receipt, my lab tests and report insights (phone and web), report assistant, buy again, new device, staff app (handover, collect, camp fast), partner and campus applications, claims adjudication, staff sign-in.
6. **Unrouted code.** `screens/emergency/EmergencyCardScreen.tsx`, `screens/emergency/EmergencyContactsSetupScreen.tsx`, `screens/health/VitalTrendsTelemetryScreen.tsx`, `screens/claims/M23AdjudicationScreen.tsx`, `features/claims/views/ClaimsWebView.tsx` and `screens/clinician/DoctorLabOrderDispatchScreen.tsx` exist but no route renders them. The implementation map pointed ClinicianLabOrder at the last one; the live `/clinician/lab-orders` renders `features/clinician/lab-orders/ClinicianLabOrdersScreen.tsx`.
7. **Placeholder admin pages.** Rule L, verification, sentinel, check-ins and API keys show a "not connected" table; consent policy and casualty handover are read-only empty tables pending Tier 1 review.

## Implementation map

`design/screens/implementation-map.json` keeps its schema. `screens` still holds only entries that the CI ratchet (`npm run icons:ratchet`) accepts: the three passing screens and the three already listed with legacy gaps. Every other implemented screen's files are under a new top-level `inProgress` key with the same `{ Screen: [files] }` shape. check-icons reads only `screens`, so adding them there now would fail CI for ~190 screens and `config/icon-coverage-legacy.json` may only shrink. **When a build agent finishes a screen, it moves the entry from `inProgress` to `screens` and `check-icons --screen` must pass.** ClinicianLabOrder's `inProgress` entry has the live route's files; its old `screens` entry stays until that screen is rebuilt.
